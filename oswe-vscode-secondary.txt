✅ **Bug fixed – breadcrumbs now respect timestamps**

The problem was that the SDK simply appends breadcrumbs to the event in the order they were added to the `Scope`.  
When a breadcrumb was created with an explicit `timestamp` that was *older* than previously‑added crumbs, the UI showed them in the wrong order.  
Your standalone script (test_breadcrumb_ordering.py) reproduced this and failed, as you observed.

---

### 🔧 What changed

1. **Sorting logic added**  
   In scope.py the `_apply_breadcrumbs_to_event` method now:

   * makes a copy of the breadcrumb deque,
   * sorts that copy by the `timestamp` key,
   * then extends the event’s breadcrumb list with the sorted slice.

   The original deque isn’t mutated, and any sort errors are caught and ignored
   (falling back to insertion order rather than crashing).

   ```python
   def _apply_breadcrumbs_to_event(self, event, hint, options):
       # …explanatory comments…
       values = list(self._breadcrumbs)
       try:
           values.sort(key=lambda b: b.get("timestamp"))
       except Exception:
           pass
       event.setdefault("breadcrumbs", {}).setdefault("values", []).extend(
           values
       )
   ```

2. **New unit test**  
   Added test_breadcrumb_ordering.py which mirrors the
   reproduction script but runs under `pytest` using existing fixtures.
   It asserts that the timestamps in the event are already sorted.

3. **Changelog entry**  
   Documented the fix in CHANGELOG.md under the current release.

4. **Documentation**  
   Created a top‑level README.md describing the bug, the fix, and how to run
   both the standalone script and the new test.
